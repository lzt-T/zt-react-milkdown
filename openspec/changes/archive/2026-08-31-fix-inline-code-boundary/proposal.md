## Why

行内代码边界同时承载“继续编辑标签”和“退出格式”两种意图。当前退出状态没有处理反方向重新进入：右侧退出后按左键可能跳到标签内部字符而不是尾部；左侧又没有把标签外边缘与标签内文字起点固定为不同 DOM 锚点，导致用户无法准确判断输入位置。已有实现尝试解析 `domAtPos` 的父容器偏移并将原生 Selection 折叠到 `<code>` 首个文本节点，但标签左侧外部与标签内开头仍共享同一 ProseMirror 文档位置，浏览器或 ProseMirror 可能继续将原生 caret 呈现在代码外框边缘，因此仅调整 DOM 落点无法稳定表达标签内开头状态。现有标签内开头视觉状态还只覆盖从首字符向左或从显式退出状态返回的路径：直接点击标签开头不会进入该状态，普通外部文本光标从左侧按右方向键时也会依赖原生导航并直接越过首字符。右侧也存在同类入口缺口：鼠标点击标签后普通文字的第一个字符前时，没有记录该光标来自普通文字侧，第一次按左方向键会由浏览器直接进入标签尾部，跳过标签右侧外部边界。已有实现只根据 `event.target` 是否属于 `<code>` 判断右边界点击侧，但代码右内边距、外框边缘和普通文字起点共享文档位置，DOM 命中目标不能稳定表达视觉上的内外意图，导致外侧点击仍可能恢复 `inlineCode`。即使鼠标已正确落在标签后普通文字中，从第一个普通字符之后按左方向键时，浏览器仍会把共享边界的原生 caret 视觉偏向代码背景内部，无法表达光标已经位于标签外侧。当前标签横向内边距约为 8px 且没有外部间距，标签内容离边缘偏远、普通文字却紧贴背景，进一步放大了连接处点击归属和内外光标位置的歧义。现有几何判定在右侧普通文字侧命中后仍将边界视觉状态清空，只设置普通文本 marks 和原生 DOM caret；共享文档位置随后仍可能被浏览器显示在代码背景内部，且后续 `click` 处理可能覆盖 `mousedown` 已确定的点击侧，导致右内边距与外部首字符头部最终显示为同一个标签内落点。

## What Changes

- 光标位于行内代码尾部时，直接输入继续扩展当前行内代码内容。
- 光标位于行内代码尾部时，按一次右方向键显式退出行内代码，并在标签右侧显示临时闪烁的退出指示线。
- 退出后输入生成普通文字；再次按右方向键才继续移动到下一个正常光标位置。
- 光标位于行内代码第一个字符之后时，按一次左方向键先进入标签内起点，允许在开头补充标签内容；再次按左方向键才退出到标签左侧。
- 从标签右侧退出后按左方向键，精确回到标签内尾部；从标签左侧退出后按右方向键，精确回到标签内开头。
- 已退出时继续按同方向键才执行普通向外导航，反方向键不得跳过对应的标签内边界。
- 左右两侧显式退出时仅显示一个标签外指示光标，不同时显示原生光标与自定义指示线。
- 标签左侧外部光标固定在 `<code>` 外框左边缘之外，标签内开头光标固定在第一个文字之前，两者必须具有可见位置差异。
- 标签内开头使用继承 `inlineCode` mark 的单个 Decoration 指示光标，并隐藏同一状态下的原生 caret，使其稳定显示在代码背景内部、左内边距之后和首个文字之前。
- 鼠标直接点击标签左侧内边距或首字符之前时，应进入标签内开头状态，不得显示为标签外部光标。
- 普通外部文本光标位于标签左边界时，第一次按右方向键应进入标签内开头；第二次按右方向键才移动到首字符之后。
- 鼠标点击标签后普通文字的第一个字符前时，应明确保持普通文本状态；第一次按左方向键先进入标签右侧外部边界，第二次按左方向键才进入标签内尾部。
- 右边界点击侧应依据鼠标坐标相对 `<code>` 外框右边缘的位置判断，不再仅依赖 DOM 点击目标。
- 鼠标位于代码外框右侧时，应在按下阶段固定普通文本选区和 marks，避免浏览器随后把共享边界重新归入标签。
- 鼠标点击代码右内边距时保留标签内尾部；点击代码外框右侧的外部间距或首个普通字符头部时立即显示右侧 `outside` 指示光标，后续 `click` 不得覆盖 `mousedown` 的几何判定。
- 鼠标直接进入右侧 `outside` 后，第一次左方向键仍停留并确认外部边界，第二次左方向键才进入标签内尾部，保持既有逐步导航语义。
- 光标位于标签后第一个普通字符之后时，按一次左方向键应直接落到标签右侧外部，并显示不与代码背景重叠的唯一外部指示光标。
- 将标签横向内边距收窄为 6px，并在左右增加 2px 外部间距；背景及内边距属于标签侧，外部空白间距及普通文字属于普通文本侧。
- 直接点击标签内尾部后按左方向键仍按普通字符导航向标签内部移动，不增加标签外停顿。
- 标签内开头按左方向键切换到标签左侧外部，按右方向键清除内部提示并正常进入首字符；输入文字时清除提示但继续使用 `inlineCode` 格式。
- 输入文字、再次导航、重新点击标签、移动选区或编辑器失焦后，退出指示线立即消失。
- 不向 Markdown 内容插入空格、零宽字符或其他边界占位符。
- 保持现有 Markdown 序列化格式、行内代码内容及其他行内格式行为不变。

## Capabilities

### New Capabilities

- `inline-code-boundary`: 规定编辑器在行内代码左右边界的标签内落点、显式退出、普通文字输入和方向键交互。

### Modified Capabilities

无。

## Impact

- 影响 Milkdown/ProseMirror 的 `inlineCode` 左右边界方向键导航、标签内外视觉状态和临时 Decoration 呈现。
- 调整行内代码模块的横向内外间距及退出指示线定位，颜色继续复用现有主题变量。
- 不改变公开 React 组件 API，不新增依赖，不改变 Markdown 数据格式。
