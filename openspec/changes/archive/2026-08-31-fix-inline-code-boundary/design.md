## Context

参见 `proposal.md` 的问题说明。Milkdown commonmark 的 `inlineCode` 默认使用包含边界，使光标位于尾部时可以继续扩展行内代码。当前变更已实现的 `inclusive: false` 会让尾部直接落在格式外，无法满足用户补充标签内容的需求，必须撤销。

## Goals / Non-Goals

**Goals:**

- 保留行内代码开头补充和尾部追加内容的能力。
- 使用左右方向键在对应文档边界上显式切换到标签外侧。
- 从退出状态按反方向键时精确返回同侧标签内边界，不依赖浏览器原生导航决定落点。
- 让鼠标直接点击标签开头和普通外部光标向右移动都先进入标签内开头，不得越过首字符。
- 让标签右侧普通文字光标向左移动时先经过标签外边界，再进入标签内尾部。
- 让光标从标签后第一个普通字符之后向左移动时，立即以标签外部指示光标呈现共享边界，不得视觉落入代码背景。
- 通过较小的标签内边距和独立外部间距，让连接处的点击区域及标签内外光标位置可直接辨认。
- 退出时仅显示紧邻对应标签外边缘的单个闪烁指示光标，消除原生光标与指示线并存的歧义。
- 让左侧外部边缘与标签内文字起点具有稳定、可见的位置差异。

**Non-Goals:**

- 不将行内代码 mark 改造成自定义节点。
- 不改变行内公式等原子节点的方向键导航。
- 除横向内外间距外，不改变行内代码的颜色、圆角、字体、Markdown 语法或工具栏命令入口。

## Decisions

### 保留 Milkdown 默认的包含边界

移除 `inclusive: false` schema 覆盖和为该覆盖补充的连续输入插件，恢复 Milkdown 默认的 `inclusive: true`。光标点击或从内部移动到行内代码尾部时继续继承 `inlineCode` mark，直接输入即可追加标签内容。

备选方案是继续使用非包含边界并判断点击方向，但同一 ProseMirror 文档位置无法可靠区分用户要编辑标签还是退出标签，因此不采用。

### 使用内外间距建立可点击的视觉分界

行内代码横向内边距从当前 `px-2` 的 8px 收窄为 `px-1.5` 的 6px，减少标签文字到背景边缘之间过大的空白；同时增加 `mx-0.5` 的 2px 左右外部间距，使代码背景不再与相邻普通文字直接相接。纵向内边距、圆角、颜色和字体保持不变。

`<code>` 的 border box 是标签内外点击归属的唯一几何分界：鼠标横坐标位于 border box 内时，包括文字和 6px 内边距，都属于标签内部；位于 border box 外的 2px margin 区域及普通文字区域时，都属于普通文本侧。右边界继续使用现有外框几何判定，左边界补充相同的外框判定，不使用背景颜色或文本节点命中结果猜测点击侧。

左右 `outside` Decoration 应显示在对应的 2px 外部间距中，位于代码 border box 之外且不覆盖相邻普通文字。标签内起点及尾部光标继续位于代码背景内部，借助 6px 内边距与外部 2px 间距形成稳定的视觉层级。外部间距仅属于 CSS 布局，不向 ProseMirror 文档或 Markdown 插入空格。

### 使用方向映射建立左右边界导航

行内代码边界导航插件通过固定的方向映射统一处理无修饰键的 `ArrowLeft` 和 `ArrowRight`，避免为左右方向堆叠重复分支。插件只处理空文本选区和 `inlineCode` 相邻边界，其他场景立即放行。

按键分发首先读取退出状态，而不是先执行普通边界判断。按键方向与退出方向相同时，插件清除退出提示并放行普通向外导航；按键方向指向标签内部时，插件阻止原生行为、清除退出状态、恢复包含 `inlineCode` 的 stored marks，并将选区保持在退出状态记录的同一文档边界。右侧外部按左键恢复到标签内尾部，左侧外部按右键恢复到标签内开头。

当没有边界视觉状态、普通文本光标位于连续 `inlineCode` mark 的左边界且用户按右方向键时，插件同样阻止原生导航，显式恢复相邻节点的真实 `inlineCode` stored marks，将文本选区保持在同一文档位置并创建左侧 `inside` 视觉状态。这样第一次右方向键只完成从标签外到标签内开头的切换，仍位于首字符之前；`inside` 状态下的第二次右方向键才清除提示并放行普通导航，进入首字符之后。

当没有边界视觉状态、普通文本光标位于连续 `inlineCode` mark 的右边界且显式输入 marks 不包含 `inlineCode` 时，插件阻止第一次左方向键的原生导航，将选区保持在同一文档位置并创建右侧 `outside` 视觉状态，同时继续保留普通文本 marks。第二次左方向键再复用现有右侧退出状态的反向重入逻辑，恢复相邻节点的真实 `inlineCode` mark 并将 DOM caret 精确放到标签内尾部。第一次左方向键后的输入仍使用普通文本格式。

当光标位于标签后普通文本的第一个字符之后时，按键发生前的文档位置还不属于共享右边界，不能等待浏览器完成原生左移后再判断。插件应在左方向键分发中先识别“左侧只有第一个普通字符，且该字符之前紧邻真实 `inlineCode` 右边界”的入口，阻止原生导航，将文本选区显式移动到该字符之前，继承普通文本 marks，并直接创建右侧 `outside` 视觉状态。这样一次左方向键同时完成普通字符回退和标签外侧视觉落点，下一次左方向键才按既有反向重入规则进入标签内尾部。

右侧 `outside` Decoration 的视觉位置不能只依赖共享文档位置和浏览器 DOM caret 偏向。实现应解析相邻真实 `<code>` 的外框，并确保唯一指示线的可见边缘位于 `codeRect.right` 之外，不继承 `inlineCode` mark、不落入代码背景；边界状态激活期间继续隐藏原生 caret。若 Decoration 的默认 DOM 落点仍与代码背景重叠，应根据指示线与代码外框的实际矩形修正其水平偏移，而不是改变文档内容。

第一次按右方向键时，插件阻止原生跨段移动，并显式设置不包含 `inlineCode` 的 stored marks，表示光标已位于标签外侧。第二次按右方向键时，当前状态已不再继承 `inlineCode`，插件放行原生导航。

左侧需要额外区分“到达标签内起点”和“退出标签”。当光标位于第一个字符之后并按左方向键时，插件先将文本选区放到该段连续 `inlineCode` mark 的起点，显式保留 `inlineCode` stored mark，并将原生 DOM 光标偏向 `<code>` 内侧。用户此时输入会在标签开头补充内容；只有光标已位于该标签内起点时再次按左方向键，插件才移除 `inlineCode` stored mark 并进入标签左侧退出状态。

stored marks 只表达 ProseMirror 格式状态，不足以保证用户看到光标移动。右侧内部落点继续从实际 `<code>` DOM 定位到最后一个文本节点末尾；标签外部继续由位于 `<code>` 外框边缘的 Decoration 表示。左侧标签内开头不再依赖原生 DOM caret，而由独立视觉状态和 Decoration 表示。该视觉调整不创建文档节点，也不改变 Markdown。

左边界的标签外侧与标签内起点共享同一 ProseMirror 文档位置。即使 `domAtPos(position, 1)` 成功解析 `<code>` 并将原生 Selection 折叠到首个文本节点 offset 0，浏览器或 ProseMirror 仍可能把 caret 规范化到等价的代码外框位置，因此不再把左侧原生 DOM 落点作为视觉状态来源。

插件状态从单一退出状态扩展为边界视觉状态，记录文档位置、左右方向以及 `inside` 或 `outside` 位置。左侧标签内起点状态保留 `inlineCode` stored mark，并创建继承真实 `inlineCode` mark 的 `Decoration.widget`，使 widget 参与 `<code>` mark 包裹并显示在代码背景内部；左侧和右侧外部状态继续使用空 marks，并分别以负 side 和正 side 渲染在代码外框之外。装饰元素不允许编辑、不响应指针事件、不参与无障碍朗读，也不写入编辑器文档。

左侧外部 Decoration 必须锚定在 `<code>` 外框左边缘之外，不得继承 `inlineCode` mark；左侧内部 Decoration 必须继承相邻节点的真实 `inlineCode` mark，并位于左内边距之后、首个文字之前。两种状态通过代码标签左侧内边距形成稳定间隔；右侧继续区分最后一个文字之后与外框右边缘之外。

边界视觉状态激活时，插件在 ProseMirror 根元素设置单一状态类以隐藏原生 caret，只保留 Decoration 指示光标；状态清除或插件销毁时同步移除该类。左侧内部状态按左方向键时切换为左侧外部状态并移除 `inlineCode` stored mark，按右方向键时清除视觉状态并放行普通向内导航。内部状态输入导致文档变化时清除视觉状态，但输入继续使用已保留的 `inlineCode` stored mark。外部状态、重新点击、选区离开边界和编辑器失焦继续沿用现有清理规则。样式继续放在行内代码模块 CSS 文件中并使用现有主题变量。

点击处理不再以已有边界视觉状态为前提。当点击目标属于 `<code>`，且点击位置命中该连续行内代码的起点、左侧内边距或首字符之前时，插件显式将文本选区保持在代码起点，恢复相邻节点的真实 `inlineCode` stored marks，并创建左侧 `inside` 视觉状态。点击标签内部尾部时保留 `inlineCode` 输入状态，使左方向键继续执行普通字符导航。

标签尾部内外侧也共享同一 ProseMirror 文档位置，仅根据 `event.target.closest('code')` 不能稳定表达鼠标意图：代码右内边距和普通文字起点可能被映射到同一位置，浏览器还可能在点击完成后重新规范化选区与 marks。因此右边界点击侧改在 `mousedown` 阶段判定，不再等待普通 `handleClick`。

插件通过 `view.posAtCoords({ left: event.clientX, top: event.clientY })` 取得鼠标对应的文档位置，确认该位置左侧为真实 `inlineCode`、右侧为普通文本后，从实际边界 DOM 解析 `<code>` 元素并读取 `getBoundingClientRect()`。鼠标横坐标位于代码外框右边缘之外时视为普通文字侧；位于代码背景或右内边距范围内时视为标签内尾部。DOM 目标只作为无法取得边界几何信息时的保守回退，不再作为主要判定依据。

普通文字侧命中后，插件在 `mousedown` 阶段阻止原生选区更新，显式将文本选区固定在共享右边界，设置不包含 `inlineCode` 且继承右侧普通文本的 stored marks，并立即创建位于 2px 外部间距内的右侧 `outside` 视觉状态。不能继续将视觉状态留空并依赖原生 DOM caret，因为共享文档位置会被浏览器显示在代码背景内部。

右侧鼠标判定不能假设 `posAtCoords` 总是直接返回共享边界。鼠标位于外部间距或首个普通字符头部时，坐标可能解析到普通文本起点或边界任一侧；处理器应检查当前位置及相邻候选位置，找到“左侧为真实 `inlineCode`、右侧为普通文本”的连续 mark 右边界，再使用 `event.clientX` 与该 `<code>` 的 `codeRect.right` 比较点击侧。无法解析唯一边界、右侧为非文本原子节点或无法取得真实代码外框时继续保守放行。

鼠标直接创建的右侧 `outside` 状态还需要区分“已显示外部落点”和“已由第一次左方向键确认”的导航阶段。第一次左方向键只把鼠标入口推进到可反向重入阶段，视觉仍停留在同一右侧外部间距且继续使用普通文本 marks；第二次左方向键才复用既有反向重入逻辑进入标签内尾部。这样既能让点击后立即显示真实外部位置，又不改变既有两次左方向键逐步进入标签的语义。该阶段信息属于临时插件状态，不写入文档。

标签内尾部命中时应清除任何右侧外部视觉状态、恢复真实 `inlineCode` mark，并保留标签内原生 caret；点击代码其他内容位置继续使用浏览器与 ProseMirror 的普通定位。由于 `mousedown` 已经完成右边界的唯一几何判定，随后触发的 `handleClick` 必须识别并保留本次已处理结果，不得再依据 `event.target` 清除或反转右侧状态。既有显式退出、首字符回退与反向重入逻辑保持不变。

备选方案是在文档中插入空格或零宽字符创建第二个位置，但会污染 Markdown 内容，因此不采用。将行内代码改成有内容的自定义 inline node 可以产生真实的内外位置，但会扩大 schema、命令和序列化改造范围，也不采用。

### 仅处理行内代码边界

本次行为只针对 `inlineCode`。粗体、斜体、删除线和链接具有不同的连续输入预期，将逻辑推广到所有 mark 会扩大范围并引入推测性行为。

## Risks / Trade-offs

- [风险] 同一文档位置需要通过 DOM 偏向呈现不同视觉侧 → 将低层 DOM 落点逻辑封装在行内代码插件内，并只在第一次右边界退出时执行。
- [风险] 装饰光标影响文档排版或原生选区 → 使用零宽、不可编辑且不响应指针事件的 widget，仅承担视觉提示。
- [风险] 原生光标与 Decoration 同时出现造成双光标 → 退出状态统一隐藏原生 caret，并在状态清理和插件销毁时恢复。
- [风险] 左键从第一个字符直接越过标签内起点 → 识别连续 mark 起点，先写入明确的标签内选区和 stored mark，再允许下一次左键退出。
- [风险] 退出后反方向键由浏览器决定落点而跳过首尾边界 → 退出状态优先消费反方向键，并显式恢复首个或末尾文本节点的 DOM caret。
- [风险] 左侧内外光标映射到同一 DOM 坐标 → 分别锚定 `<code>` 外框边缘和首个文本节点，使用标签内边距建立视觉间隔。
- [风险] 左侧原生 Selection 被浏览器或 ProseMirror 规范化到等价的外框位置 → 标签内开头改用继承 `inlineCode` mark 的单一 Decoration，并在该状态隐藏原生 caret。
- [风险] 直接点击标签开头时没有既有视觉状态，点击处理提前放行 → 根据点击目标和代码起点创建 `inside` 状态，不要求先存在边界状态。
- [风险] 普通外部光标按右方向键由浏览器直接越过首字符 → 在无视觉状态的左边界增加向内入口，第一次按键只进入 `inside` 状态。
- [风险] 标签右侧普通文字光标与标签内尾部共享文档位置，第一次左键直接进入标签 → 在 `mousedown` 阶段根据鼠标坐标与代码外框右边缘区分点击侧，普通文字侧先清除 `inlineCode` stored mark，再由第一次左键创建右侧 `outside` 状态。
- [风险] 右侧外部入口误拦截标签内尾部的普通左键导航 → 仅在显式输入 marks 不含 `inlineCode` 时创建右侧 `outside` 状态，代码侧点击继续保留 `inlineCode`。
- [风险] 视觉上位于标签外的点击仍命中 `<code>` 或被点击后的原生选区重新归入标签 → 对几何判定为外侧的 `mousedown` 阻止原生选区更新，并显式固定边界选区与普通文本 marks。
- [风险] 外侧点击只清除 `inlineCode` marks 但视觉状态为空，原生 caret 仍显示在代码背景内部 → 鼠标外侧命中后立即创建带鼠标入口阶段的右侧 `outside` 状态，并隐藏原生 caret。
- [风险] `posAtCoords` 在首个普通字符头部返回边界相邻位置，导致右边界处理器提前放行 → 从当前位置与相邻位置解析唯一的连续 mark 右边界，再执行外框几何判定。
- [风险] `mousedown` 已判定外侧但后续 `click` 再次按 DOM target 清除状态 → 记录本次右边界鼠标处理结果，使 `handleClick` 不再覆盖同一次指针交互。
- [风险] 从第一个普通字符之后原生左移到共享边界时，caret 仍视觉落入代码背景 → 在按键前识别首字符回退入口，显式创建右侧 `outside` 状态，并以 `<code>` 外框校正指示线位置。
- [风险] 缩小内边距后标签内点击区域不足，或增加外间距后点击归属仍不清楚 → 保留 6px 内边距和 2px 独立外间距，并统一以 `<code>` border box 作为左右两侧几何判定线。
- [风险] 坐标解析误拦截相邻行内公式或其他原子节点 → 仅在右侧相邻节点为普通文本且能解析真实 `<code>` 外框时执行几何判定，其他情况立即放行。
- [风险] 退出指示线在失效状态残留 → 根据输入、导航、点击、选区和焦点变化统一清除。
- [风险] 点击同一边界可能保留标签外 stored marks → 点击命中行内代码尾部时显式恢复标签内状态。
- [风险] 方向键插件与行内公式导航共存 → 仅在左侧文本节点带有 `inlineCode` mark 时处理，其他场景立即放行。

## Migration Plan

该调整不涉及数据迁移。实施时先移除当前错误的 schema 覆盖和连续输入插件，再接入新的右边界导航插件；回滚时移除导航插件即可恢复 Milkdown 默认行为。
