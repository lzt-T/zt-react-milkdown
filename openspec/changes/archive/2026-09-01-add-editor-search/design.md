## Context

参见 `proposal.md` 的动机和 `specs/editor-search/spec.md` 的行为约束。当前 React 根组件负责编辑器容器、主题、只读状态和两层 Portal；`useMilkdownEditor` 管理 Milkdown 生命周期；`createMilkdownEditorRuntime` 统一装配 ProseMirror 插件，并已通过可变 ref 向 React 暴露聚焦能力。项目使用 pnpm、Milkdown 7.21.1 和由 `@milkdown/prose` 提供的 ProseMirror 类型。

搜索栏是编辑器固定控件而非锚点浮层：它需要在 `maxHeight` 编辑区滚动时保持可见，也不应挂载到 `document.body`。代码块预览状态由 NodeView 管理，源码仍存在于 ProseMirror 文档中，但在预览模式下不可见。

## Goals / Non-Goals

**Goals:**

- 将搜索 UI 状态与 ProseMirror 匹配状态通过窄接口连接，避免把原生 EditorView 放入 React state。
- 复用成熟搜索算法和 ProseMirror transaction，保持替换、撤销、受控值同步和多实例隔离一致。
- 让搜索栏在主题、只读、内部滚动和中英文环境中表现一致。
- 在完整保留搜索选项与替换能力的前提下，通过渐进展开降低搜索栏默认视觉密度。
- 保持修改集中在搜索能力及必要的现有装配点，不重构无关插件。

**Non-Goals:**

- 不搜索 Markdown 序列化后的标记字符。
- 不搜索图片属性、公式源码或其渲染 DOM，也不穿透代码预览 iframe。
- 不提供跨编辑器、跨页面或服务端搜索。
- 不新增全局事件总线或全局键盘监听器。

## Decisions

### 1. 使用 `prosemirror-search` 作为搜索内核

通过 pnpm 引入与当前 ProseMirror 依赖兼容的 `prosemirror-search`，复用其查询、匹配装饰、导航和替换命令；项目仅添加一层适配器，用于结果计数、错误快照、循环导航、捕获组替换和 React 回调。

`prosemirror-search` 的 `search()` 和项目的搜索快照插件均为原生 ProseMirror `Plugin`。运行时必须分别通过 `@milkdown/utils` 提供的 `$prose` 包装为 Milkdown 插件函数，再交给 `Editor.use()` 装配。原生插件继续负责状态、事务和 Decoration，`$prose` 仅负责适配 Milkdown 生命周期与插件类型边界，不改变搜索行为。

选择该方案是因为它直接操作 ProseMirror 文档位置和事务，能够正确处理跨行内 mark 的文本，并与历史记录协作。备选方案是遍历 DOM 或自行扫描文档并维护 DecorationSet；前者无法可靠映射文档位置，后者会重复实现成熟能力并扩大维护面。

搜索插件在编辑器启动阶段随其他文档插件注册，不放入仅包含 clipboard 和 indent 的延迟运行时插件集合。

### 2. React 管理表单状态，ProseMirror 插件管理匹配状态

`MilkdownEditor` 管理搜索栏开关、替换区展开状态、查询文本、替换文本和三个选项。搜索插件持有与文档位置相关的匹配、高亮和当前项状态，并通过轻量快照向 React 报告当前索引、总数和校验错误。展开状态仅影响界面呈现，不清空替换文本、查询或插件匹配状态。

在运行时增加与现有 `focusEditorRef` 同类的搜索控制器 ref，提供更新查询、上一项、下一项、替换当前项、全部替换和清理操作。这样避免将 EditorView 存入 state，也避免查询输入导致 Milkdown 重建。备选方案是让 React 直接读取 Milkdown context；这会扩大组件与 Milkdown 生命周期的耦合。

### 3. 在编辑器根节点捕获实例内快捷键

在 `.zt-md` 根节点使用 React `onKeyDownCapture` 处理当前实例内的 `Ctrl/Cmd+F`。捕获阶段覆盖 ProseMirror、搜索输入框和其他实例内控件，同时不会影响焦点位于实例外时的浏览器查找。同一处理器负责搜索栏中的 `Escape`、`Enter` 和 `Shift+Enter` 分发，不注册 `document` 级监听器。

打开搜索栏后通过 ref 聚焦并选中查询输入；关闭时清理插件查询和 Decoration，并聚焦当前匹配或编辑器内容。

### 4. 搜索栏直接渲染在 `.zt-md-body` 并渐进展开替换区域

新增独立 `SearchPanel` React 组件，作为 `.zt-md-body` 的直接子节点，以绝对定位方式固定在右上角。它不使用 `.zt-md-portal` 或 `.zt-md-content-portal`，因此不会随 `.zt-md-editor` 的 `maxHeight` 滚动视口被裁剪。搜索打开时通过根节点数据属性避免与只读标签重叠。

桌面端主行集中搜索输入、大小写、全词、正则、结果计数、导航、关闭和替换区展开控件。搜索输入占据主要可用宽度；大小写、全词和正则组成统一的紧凑分段控制；替换展开、上一项、下一项和关闭使用同一图标按钮尺寸与低对比默认态，导航与关闭通过间距或细分隔建立职责边界。替换输入、替换当前项和全部替换默认隐藏，仅在用户显式展开后显示为第二行；收起时保留替换文本。替换当前项使用较强操作层级，全部替换保持次级层级。只读模式不展示替换区展开控件。相比始终展示三行表单，该结构让高频搜索和导航保持紧凑，同时不移除任何能力。

样式放入独立 `src/styles/modules/search.css`，仅使用既有主题 token 和语义变量，并由 `src/styles/style.css` 导入。面板、输入、分段选项和图标按钮遵循现有圆角体系，默认态透明或使用低对比表面色，选项激活态使用主题色浅底与主题色文字，悬停、按下、键盘焦点和禁用态保持一致。桌面端统一紧凑控件高度与间距，避免披露按钮呈现为孤立的实心方块。窄屏布局按主行和替换行职责换行，输入与按钮保持至少 44px 的触控目标；所有图标按钮复用当前 `lucide-react` 依赖，不新增图标或组件依赖。

### 5. 查询、导航、滚动与替换语义

普通查询默认不区分大小写；大小写、全词和正则选项组合为单一查询对象。适配器在派发查询前验证正则，失败时清除装饰、上报本地化错误并禁止命令。查询或文档变化后，插件重新计算结果并尽量保持当前匹配；原位置失效时选择下一项，没有结果时回到零状态。

导航命令在边界处显式循环。上一项、下一项和替换当前项仍在命令事务中保留 ProseMirror `scrollIntoView()` 元信息，但不再将其作为内部滚动成功的唯一保证。导航事务派发后，定位逻辑通过当前 EditorView 的选区位置取得匹配起止坐标，复用 `resolveEditorWrapper(view.dom)` 解析该实例的 `.zt-md-editor`，并比较匹配矩形、滚动容器矩形和搜索面板底部形成的安全可见区域。仅当匹配超出安全区域时计算垂直差值并调整当前容器的 `scrollTop`，不调用页面级滚动，也不查询或修改其他编辑器实例。

搜索栏位于滚动容器外，编辑区继续根据替换区域是否展开预留相应顶部空间。显式滚动计算同时保留小幅上下边距，并将搜索面板实际底部作为顶部安全线，避免不同语言、窄屏换行或替换区高度变化导致当前匹配被遮挡。匹配已经完整可见时不改变滚动位置，减少无意义跳动。

若当前匹配属于预览模式代码块的源码，定位逻辑复用现有预览切换按钮，将该 NodeView 切换到源码模式，并在下一次动画帧等待视图 DOM 更新后重新获取匹配坐标和执行同一实例级滚动；不尝试搜索 iframe 内部。滚动始终由当前实例的 EditorView 发起，只修改该实例解析出的 `.zt-md-editor.scrollTop`。

替换当前项使用一次事务，随后选择下一项。全部替换从后向前构建同一个事务，避免位置偏移，并保证一次撤销即可恢复。正则替换由搜索内核按每个匹配展开 `$1`、`$2` 等捕获组。只读模式不渲染可执行的替换控件，运行时命令仍检查 EditorView 的 editable 状态作为最终边界。

### 6. 国际化和公开 API 保持增量扩展

在 `EditorI18nMessages`、`zh-CN.ts` 和 `en-US.ts` 中成组增加搜索占位、按钮、选项、无结果和正则错误文案。继续使用现有 `messages?: Partial<EditorI18nMessages>` 覆盖机制，不新增第二套语言配置，也不改变现有 props 的必填性。

## Risks / Trade-offs

- [长文档在每次输入时重新匹配可能产生延迟] → 依赖搜索内核的文档遍历与装饰增量更新；仅在查询、选项或文档变化时计算，不为结果派生额外 React state。
- [组合正则与全词匹配时边界语义可能因语言不同而变化] → 采用搜索库的 Unicode 感知边界行为，并在 README 明确中文等无空格语言仍以实际边界规则为准。
- [代码块预览状态位于 NodeView 而非文档状态] → 仅在导航到源码匹配时复用现有预览切换入口，不把预览状态迁移进 schema。
- [搜索栏展开高度变化后可能覆盖文档顶部内容或只读标签] → 搜索栏使用独立层级和响应式布局，根据替换区域展开状态调整编辑区顶部空间，并在只读模式隐藏替换入口。
- [ProseMirror `scrollIntoView()` 未驱动实际具有 `overflowY: auto` 的 `.zt-md-editor` 时，当前匹配仍可能停留在视口外] → 保留事务滚动元信息，并在事务派发和代码块视图切换后根据匹配坐标显式调整当前实例滚动容器。
- [依赖版本与 Milkdown 聚合的 ProseMirror 版本不一致] → 安装前确认 pnpm 解析到兼容的 peer dependency，直接从 `@milkdown/prose` 导入项目侧 ProseMirror 类型，避免重复实例。
- [原生 ProseMirror `Plugin` 被直接传入 Milkdown `Editor.use()` 会在初始化阶段触发 `plugin is not a function`] → 在搜索插件模块边界统一使用 `$prose` 包装，并静态核对运行时装配链只接收 Milkdown 插件函数。

## Migration Plan

1. 添加兼容依赖和搜索插件，不改变现有编辑器默认内容行为。
2. 接入运行时控制器、React 搜索栏、国际化和样式。
3. 接入替换区渐进展开、统一按钮视觉体系和实例级显式导航滚动，并核对桌面、窄屏、明暗主题及多实例边界。
4. 更新 README，明确快捷键、搜索范围、导航滚动、替换语义和只读限制。
5. 若发布后需要回滚，移除搜索栏及插件注册并撤销新增依赖；现有文档数据和组件 props 无需迁移。
