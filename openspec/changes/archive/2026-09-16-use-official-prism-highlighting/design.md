## Context

见 proposal.md 的动机。当前 Milkdown 为 7.21.1，refractor 为 5.0.0，项目使用 pnpm 锁文件。已读取官方 `@milkdown/plugin-prism@7.21.1` 发布包声明及源码：依赖匹配当前版本，导出 `prism` 插件集合和 `prismConfig`，以 `configureRefractor` 配置语法。

当前已完成官方插件迁移、刷新适配及默认语言集加 Dart 的注册；代码块 schema 将缺省语言规范化为 `text`，现有主题消费 Prism `.token` 类名。此前进程内集成诊断只覆盖原语言范围，不代表本次全量加载方案已经通过验证。

## Goals / Non-Goals

**Goals:** 使用官方插件承担 token 装饰生成；同步支持当前 refractor 版本的全部语法及别名，使语言选择器与高亮配置一致；满足 code-block-highlighting 规格。

**Non-Goals:** 不引入 CodeMirror、异步语言加载、额外依赖或新的公共配置 API；不手工维护全语言名称表；不重构已有大型选择器、主题或搜索模块。

## Decisions

### 官方插件替换自定义装饰实现

添加精确版本 `@milkdown/plugin-prism@7.21.1`，通过现有插件描述列表装配其 `prism` 集合。现有装配工具支持插件数组，无需另建插件管理机制。删除此次替换导致无用的 `code-block-prism.ts` 及其导出，保留代码块 NodeView 与其他插件。

相比仅给自定义插件补 Dart，这一方案符合已确定的官方插件迁移方向；相比整体替换代码块组件，影响范围更小。

### 单一语言注册来源

现有 `code-block-highlighter.ts` 改从 `refractor/all` 导入并导出实例，移除 `refractor/dart` 单独导入和注册，保留 text 空语法注册。全量语法由模块加载时一次性注册，不在每次高亮刷新时遍历重新注册。语言选择器继续从共享模块读取列表，菜单与当前语言按钮直接显示规范化语言标识，复用既有搜索、排序和纯文本国际化文案。

移除 `LANGUAGE_LABEL_MAP` 及失去用途的 `resolveLanguageLabel`。普通菜单项直接以语言值作为 label，当前按钮使用已有的 normalizedCurrentLanguage；当值为 text 时，两处均使用 messages.codeBlockLanguagePlainText。别名按自身标识展示，例如 js、sh，不合并为语言全名；搜索继续不区分大小写。不改变语言值、Markdown 输出、高亮实现或公共 API，也不扩大清理到无关映射表。

`refractor/all` 与官方插件导入的默认入口均导出同一 core 实例。保留 `prismConfig.configureRefractor` 对官方传入实例注册 text，确保官方插件和菜单读取已全量注册的同一实例；不依赖回调返回替代实例。保留 refractor 直接依赖，验证模块实例一致性及锁文件解析结果，避免菜单与高亮器分离。

选择全量同步加载，以最少实现提供完整语言范围；不采用异步按需加载，避免引入语法加载状态和二次高亮调度。

### 纯文本适配

在共享注册函数中为现有 `text` 值注册空语法，使官方插件正常返回无着色文本而不输出纯文本警告。无需改变 schema、Markdown 输出或全局屏蔽 console。未知语言仍使用官方不高亮的处理，允许其诊断警告，但保留内容和语言标识。

### 保留主题与刷新语义

复用现有 code-block.css 的 token 样式和主题变量，不加载第三方主题 CSS。对 Dart 初始渲染、菜单切换、多代码块、搜索替换及撤销重做建立验收证据。

已复现官方 7.21.1 在未聚焦第二个代码块内替换关键字后残留装饰。新增 `code-block-prism-refresh.ts` 生命周期适配：执行官方 prismPlugin 初始化后，在编辑器状态创建前修改本次生成的插件状态 apply；所有 docChanged 调用官方状态 init 生成装饰，其他事务仅映射装饰。官方 key、props、配置和清理逻辑均保持不变，装配为适配插件与 prismConfig 两项，不再额外装配 prismPlugin。

此策略沿用迁移前的全量文档变化刷新成本，避免引入额外节点比较缓存、选区跳转或搜索专用补丁。代价是放弃官方部分增量优化，并在每次重算时再次执行幂等语言注册。升级官方插件时须复核其状态字段及初始化行为。不复制 token 展平或 Decoration 构造逻辑。

适配从当前编辑器的 prosePluginsCtx 按官方 7.21.1 的 `MILKDOWN_PRISM$` 实例 key 前缀取插件，避免 prismPlugin.plugin() 共享访问器在并发创建编辑器时指向另一实例。此 key 为上游实现细节，升级时需一并复核；已通过双实例并发初始化及独立编辑、销毁的进程内诊断。

## Risks / Trade-offs

- [全量语法增加包体积和初始化开销] → 获得构建脚本授权后，在相同配置下对比改动前后 ES/CJS 产物的原始及 gzip 字节数与增量；不将包体积测量等同于初始化耗时测量，未测量项明确记录，不预设性能影响很小。

- [官方刷新条件可能遗漏部分外部事务] → 重点验证非首个、未聚焦代码块的搜索替换和语言变化；失败时迁移不得标为完成。
- [默认 text 不属于内置语法] → 使用空语法注册保留既有纯文本行为，不通过吞掉全部警告掩盖问题。
- [插件描述从单项变为集合] → 检查插件名称引用和既有装配断言，保证配置上下文与高亮插件都被注册。
- [受限验证] → package.json 脚本须取得用户明确授权后执行，不直接调用脚本内容绕过限制；遵守浏览器控制禁令，动态视觉检查未执行时明确记录。

## Migration Plan

1. 在调整语言入口前，若获构建脚本授权则记录现有默认语言集加 Dart 的产物体积作为基线；未获授权则记录未测量，且不运行脚本或绕过限制。
2. 将共享模块切换到全量入口，移除单独 Dart 注册，保留官方插件、text 空语法及刷新适配；更新 README 支持范围。
3. 核对菜单与注册集合一致、别名可用及纯文本去重；验证 Dart、Scala、Elixir 的导入、切换和高亮，并回归搜索替换、撤销重做、双编辑器。
4. 在获得授权时进行同配置构建体积对比，将结果及受限验证记录到验收记录；此前验证不能替代本次全量方案验证。
5. 无持久化数据迁移，也不自动发布。全量增量的回退只需恢复默认入口和 Dart 单独注册，保留已完成的官方插件迁移及刷新适配。
