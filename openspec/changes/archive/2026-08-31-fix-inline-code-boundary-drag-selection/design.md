## Context

参见 `proposal.md` 的问题说明。当前行内代码边界插件在 `mousedown` 阶段根据鼠标坐标解析标签内外侧，随后立即阻止原生行为并创建折叠文本选区。该时机能够稳定单击边界的输入状态，但浏览器尚未获知用户是否会继续拖动，因此同一处理也阻止了原生拖拽选区建立。

标签内外侧仍共享同一个 ProseMirror 文档位置，现有基于 `<code>` 外框的几何判定、stored marks 和 Decoration 状态需要继续保留。当前鼠标命中右侧外部边界时还会记录 `requiresInwardConfirmation`，第一次向内方向键只清除该标志并阻止默认行为，因此视觉上没有位移。修复应调整鼠标事件时机及该入口的向内导航，不改动 Markdown 内容或标签样式。

## Goals / Non-Goals

**Goals:**

- 让原生鼠标按下和移动过程能够建立跨行内代码边界的非空文本选区。
- 普通单击完成后继续精确区分标签背景、内边距和外部间距。
- 鼠标已经将光标放到标签右侧普通文字开头时，第一次左方向键立即进入标签末尾。
- 复用现有边界解析、mark 与视觉状态逻辑，控制修改范围。

**Non-Goals:**

- 不调整行内代码的尺寸、颜色、Markdown schema 或序列化方式。
- 不改变从普通字符内部逐字符回退、标签内部退出及左侧边界的方向键状态链。
- 不引入自定义拖拽阈值、全局指针监听器或新的事件状态机。

## Decisions

### 将边界处理从按下阶段延后到单击阶段

取消行内代码边界对 `mousedown` 的拦截，让浏览器和 ProseMirror 正常建立鼠标选区。在现有点击入口中复用鼠标坐标、相邻节点和 `<code>` 外框几何判定；普通单击完成后，再显式设置边界选区、stored marks 与视觉状态。最终显式事务仍是单击落点的权威结果，因此不依赖浏览器对共享文档位置的默认 mark 推断。

备选方案是在 `mousedown` 后注册 `mousemove`、`mouseup` 监听并以移动距离判断拖拽。该方案需要额外的临时状态、清理逻辑和自定义阈值，而点击阶段已经天然提供了更小的处理边界，因此不采用。

### 以非空选区作为拖拽优先判定

点击处理开始时检查当前文本选区。若选区非空，说明该次指针交互已经形成文本选择，插件直接放行，不得重新折叠选区或设置边界 stored marks。若选区为空，才执行现有标签内外几何判定。

该规则同时保护从标签首尾开始的拖拽、跨标签拖拽、双击选词和三击选块。它使用编辑器最终选区而不是自行计算鼠标移动距离，与 ProseMirror 的选区语义保持一致。

### 保留现有边界策略并调整事件接线

边界上下文解析、左右侧几何比较、普通文本 marks、`inlineCode` marks 和 Decoration 状态继续由现有行内代码边界模块负责。鼠标边界处理器改为由现有 `handleClick` 路径调用，并在其成功处理后终止该次点击的其他边界推断；非边界点击继续执行原有点击清理逻辑。

不新增通用抽象或独立事件管理器，因为该行为只服务行内代码的共享文档边界。

### 鼠标右侧入口不增加二次确认

鼠标普通单击标签右侧外部间距或首个普通字符开头时，几何判定已经明确表达用户位于普通文本侧。该点击仍创建右侧 `outside` 视觉状态并保留普通文本 marks，但不再附加 `requiresInwardConfirmation`。后续第一次左方向键直接执行既有的向内恢复逻辑：恢复相邻真实 `inlineCode` mark、清除右侧外部状态，并将 DOM caret 精确放到标签末尾。

从标签后第一个普通字符之后按左方向键的入口继续先把文档选区移动到该字符之前并创建右侧 `outside` 状态。由于这次按键已经产生一次真实的字符位移，下一次左方向键再进入标签末尾，保持逐字符导航语义。

鼠标入口不再需要独立的确认标志。实施时移除边界状态中的 `requiresInwardConfirmation` 属性、向内导航对该属性的吞键分支，以及仅为保留该鼠标确认状态服务的孤儿判断；不得影响左右方向键分发表的其他处理器。

备选方案是保留确认标志并在鼠标点击后预先将其设为已确认。该方案会留下无实际语义的状态字段和分支，增加后续维护成本，因此不采用。

## Risks / Trade-offs

- [风险] 浏览器在 `mousedown` 与 `click` 之间可能短暂显示默认边界光标 → 单击完成后立即通过现有事务和 Decoration 校正最终状态，不增加文档内容。
- [风险] 拖动距离很小但最终选区为空时仍会按普通单击处理 → 以用户可观察到的最终选区为准，与浏览器原生点击语义一致。
- [风险] 点击处理顺序可能再次覆盖已确定的标签内外状态 → 边界处理成功后立即结束该次点击分发，并保留现有几何判定作为唯一来源。
- [风险] 移除鼠标确认步骤可能误改从普通字符回退的两段导航 → 只移除鼠标入口附加的确认状态，保留首个普通字符之后的回退处理器及其外部边界落点。

## Migration Plan

该变更不涉及数据迁移。实施时移除 `mousedown` 事件接线并将边界处理接入现有点击路径，同时删除鼠标右侧入口的二次确认状态；回滚时恢复原有事件接线与确认分支即可。
